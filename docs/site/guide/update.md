# 在线更新与回滚

在「系统管理 › 版本与更新」检查新版本，点「立即更新」即可。整个过程不需要手动停服务。

## 更新什么

| 内容 | 何时更新 |
| --- | --- |
| 程序 | 每次 |
| 配置包 | 新版本要求更新配置结构时 |
| WebUI | 配置目录下存在 `ui/main/` 时 |

你的规则、名单、学习结果、缓存、WebUI 里的设置和专属分流组都不受影响。配置包只替换它管理的 `config_custom.yaml` 与 `sub_config/*.yaml`。

## 安全机制

1. **先校验**：所有文件的 sha256 必须与发布清单一致；新程序必须能通过新配置的检查。任何一项不通过，什么都不改。
2. **先备份**：旧程序、旧配置、旧 WebUI 都保存在 `update/` 目录下。
3. **试运行**：新程序启动后要通过健康检查。
4. **自动回滚**：新程序启动失败、不健康或超时，自动恢复旧程序、旧配置和旧界面。

整个过程进程号不变，systemd 等服务管理器察觉不到停止；回滚也不依赖服务管理器。

## 适用范围

- 只有 Linux amd64 的程序包支持在线更新；其它架构从 [Releases](https://github.com/jasonxtt/atomdns/releases) 手动替换。
- 支持 AVX2 的机器可在更新时切换到 `amd64-v3` 优化版，版本号不变。
- Docker 版不支持在线更新，拉取新镜像并重建容器即可，配置包与 WebUI 会在启动时同步到挂载目录。

## 手动更新

```bash
systemctl stop atomdns
tar -xzf atomdns-linux-amd64.tar.gz
install -m 755 atomdns /usr/local/bin/atomdns
systemctl start atomdns
```

WebUI 解压到 `ui/main/` 即可（先删除旧目录）。新版本要求更新配置结构时，手动替换程序后配置检查会失败，此时建议使用在线更新，它会一并更新配置包。

## 配置备份

「系统管理」可以把整个配置目录导出为 zip（不含 `update/` 与 `backup/` 目录），换机器或重装时解压到新的配置目录即可。
